## Steps

- [ ] Add the three constants beside `ERROR_OUTPUT_PREFIX` (`:1685`): `LOG_RETENTION_DAYS = 365` (with a comment naming what it matches and why it is not read from `ctx.config.retention` - that block's two keys each name one of the site's own two log groups, and a third and fourth consumer would make one of them silently govern resources it was never named for), `DESTINATION_DELIVERY_STREAM = 'DestinationDelivery'`, and `FIREHOSE_LOG_GROUP_PREFIX = '/aws/kinesisfirehose/'`. Add the two node ids beside the twelve at `:133-178`.
- [ ] Give each group name exactly one home, and derive both from the name helper the writer already uses rather than re-deriving from `ctx.names.prefix`: the transform group is `${LAMBDA_LOG_GROUP_PREFIX}${transformFunctionName(ctx)}` (the string `transformLogGroupArn` already builds - factor it into a named helper both call, so the grant and the group can never name different strings), and the Firehose group is `${FIREHOSE_LOG_GROUP_PREFIX}${streamName(ctx)}`. `boundedName` throws rather than truncating, so the risk here is duplication and not silent divergence - but three spellings of the Firehose group name are coming (the node, the delivery role's fifth statement at task 04, and the destination's `LogGroupName` at task 04), and one helper is what keeps them one string.
- [ ] Write `analyticsTransformLogGroupNode()` on the `logGroupNode` contract, through `logs(ctx)` (`:2541`), with `create` ensuring the group with `ctx.tags` then applying `LOG_RETENTION_DAYS`, `update` applying the retention alone, `delete` removing the group, and `read` recording the ARN built with `ANALYTICS_REGION` and never `ctx.config.region`.
- [ ] Write `analyticsFirehoseLogGroupNode()` the same way with one delta: `create` **and** `update` both call `ensureLogStream(group, DESTINATION_DELIVERY_STREAM)` after the retention call. This is the `applyBucketConfiguration` reconcile-on-every-apply pattern rather than the site `logGroupNode`'s narrower update, and the reason is concrete: a group created by a run that crashed between `CreateLogGroup` and `CreateLogStream` is otherwise permanently one call short, with `read()` reporting it present and `update()` doing nothing about it. `delete` needs no separate stream teardown - deleting a group deletes the streams in it. `BackupDelivery` is not created; the Iceberg destination configures no S3 backup.
- [ ] Rewrite `transformLogGroupArn`'s doc comment (`:900-921`). Line `:912`'s "**No node creates this group.** Lambda creates it implicitly on the function's first invocation" is false and production disproved it. It becomes a statement that `analytics-transform-log-group` owns the group, and that the role is deliberately **not** granted `logs:CreateLogGroup` because of it - the shape the site's exec role has (`packages/cli/src/nodes.ts:214`). The function body at `:922` does not change: the ARN it derives is already correct and is now also the group the node creates.
- [ ] Fix the second false statement the spec does not name: `LAMBDA_LOG_GROUP_PREFIX`'s own doc comment at `:763-767` says the group is "created by the Lambda service on first invocation and by no node in this graph". Both halves are now wrong and it points a reader at `transformLogGroupArn` for the reasoning.
- [ ] Leave `applyTransformRolePolicy`'s logs statement (`:1032`) exactly as it is - `['logs:CreateLogStream', 'logs:PutLogEvents']`. That is the point of the design and the reason it supersedes PR #27. Extend only the doc comment above it (`:1008-1025`) to say why the third action is absent.
- [ ] Add the two edges and no others: the transform function's `dependsOn` (`:1514`) gains the transform group, and the stream's `dependsOn` (`:2297`) gains the Firehose group. Neither role's `dependsOn` changes: a role derives its log group ARN from a name it already knows, so it has nothing to wait for, while a writer that runs before its group exists loses output with nothing raised. `topoSort` drains zero-indegree nodes alphabetically (`packages/cli/src/graph.ts:46-49,59`) so both groups would happen to drain early anyway, which is precisely why the edges are declared rather than left to that.
