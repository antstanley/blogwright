## Steps

- [ ] Add `ensureLogStream(logGroupName: string, logStreamName: string): Promise<void>` directly beneath `ensureLogGroup` at `packages/core/src/aws/logs.ts:71`, sending `CreateLogStream` with `{ logGroupName, logStreamName }` and nothing else. Verify both key spellings against the CloudWatch Logs `CreateLogStream` API reference **before** writing them: the test asserts the body the implementation itself constructs and cannot catch a wrong key.
- [ ] Swallow on `err instanceof AwsError && err.isAlreadyExists`, rethrow otherwise - character-for-character `ensureLogGroup`'s catch. `ResourceAlreadyExistsException` reaches `AwsError.code` through the AWS-JSON `__type` field and matches `isAlreadyExists`'s `/AlreadyExists/i`; do not add a second, narrower predicate for it.
- [ ] Take no tags parameter. `CreateLogStream` accepts none, and a signature that mirrored `ensureLogGroup`'s would model an argument the API cannot carry.
- [ ] Add a request-body case to `packages/core/src/aws/logs.test.ts` using `capturingTransport`, asserting the whole body with `toStrictEqual` - `{ logGroupName, logStreamName }`, no third key - and asserting the `x-amz-target` header is `Logs_20140328.CreateLogStream`.
- [ ] Add the two failure cases: a `ResourceAlreadyExistsException` reply resolves without throwing, and a different failure (`ValidationException`, or a 500) rejects. The second is the negative space that makes the first mean something: a method that swallowed everything would pass the already-exists case alone.
- [ ] Watch each new assertion fail before declaring it: delete the `logGroupName` key from the body and see the body case fail; delete the `isAlreadyExists` guard and see the swallow case fail; widen the catch to swallow everything and see the rethrow case fail. Record each mutation and the failure it produced, then restore.
