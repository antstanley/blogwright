## Steps

- [x] The salt decision is SETTLED (2026-07-26): ONE long-lived random secret in Secrets Manager, with the per-day salt DERIVED as `dailySalt(secret, day) = HMAC-SHA256(secret, day)` - never derived from the date alone, and never rotated in Secrets Manager. Record it as a decision note in the module doc comment with both reasons: a date-only salt is computable by anyone holding the table and IPv4 is a 2^32 space, so the digest would brute-force in seconds; and managed rotation would add a rotation Lambda, a schedule and a second role - more moving parts than the thing they protect - for no gain over deriving. Note that replacing the stored secret after rows exist breaks unique-visitor comparison across the boundary, which is why the node never rewrites it.
- [x] Export `dailySalt(secret, day)` alongside `visitorKey(ip, userAgent, salt)`, both pure and both taking their inputs as arguments - this module reads no secret and knows no clock.
- [x] Take the salt as an ARGUMENT - `visitorKey(ip, userAgent, salt)` - so this module stays pure and testable with a pinned vector, and no part of it reads Secrets Manager. Fetching and caching the salt is task 42's envelope concern (cold-start read, cached for the execution environment's life); the node that provisions the secret and the grant is task 50's.
- [x] Write `visitorKey(ip, userAgent, salt)` in `packages/analytics/src/transform/visitor-key.ts` as a SHA-256 digest over the three inputs with an unambiguous separator, returning a hex string; the salt is a parameter derived from an injected day, never read from a wall clock inside the function.
- [x] Write the salt derivation as its own named function taking the day value the record already carries (task 40's `day`), so a test can pass two different days without stubbing time.
- [x] Write the bot matcher in `packages/analytics/src/transform/bots.ts` over a named module constant of user-agent patterns, returning a boolean for every input including an absent or empty user agent.
- [x] Rewire `mapRecord` so the viewer-IP field feeds `visitorKey` and is never assigned to a column, and so `is_bot` is always set; the record is still returned when the matcher says bot.
- [x] Write `visitor-key.test.ts` pinning a fixed secret, day, IP and user agent to a known digest for BOTH `dailySalt` and `visitorKey`; add the same-day/next-day turnover assertions (same secret, different day → different salt → different key); write `bots.test.ts` covering a known bot agent, a browser agent, an empty agent and an absent agent.
- [x] Add a whole-row assertion in the transform tests that searches every value of the produced row for the fixture IP and expects no match.
