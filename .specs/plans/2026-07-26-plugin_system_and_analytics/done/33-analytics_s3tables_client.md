## Steps

- [x] The client lives in `packages/analytics/src/aws/` and supplies its own service descriptor through task 31's transport seam. Core's `SIGNING_NAMES` gains nothing and `AwsClients` gains no `s3tables` key - a test or review step asserts `grep -rn "s3tables" packages/core/src --include='*.ts' --exclude='*.test.ts'` returns nothing.
- [x] Write `packages/analytics/src/aws/s3tables.ts` opening with a module doc comment (the `packages/core/src/aws/microvms.ts:4-11` shape) naming the protocol - REST-JSON, signed through the `{ service: 's3tables', signingName: 's3tables' }` descriptor task 31's seam accepts - and stating that the floci emulator does not implement the service, so it is covered by transport mocks.
- [x] Declare a `PATHS` table in the `packages/core/src/aws/microvms.ts:15-21` shape covering `PUT /buckets`, `GET|DELETE /buckets/{tableBucketArn}`, `PUT /namespaces/{tableBucketArn}`, `GET|DELETE /namespaces/{tableBucketArn}/{namespace}`, `PUT /tables/{tableBucketArn}/{namespace}`, `DELETE /tables/{tableBucketArn}/{namespace}/{name}` and - CORRECTED 2026-08-30 - `GET /get-table` with `tableBucketARN`, `namespace` and `name` as QUERY parameters, not URI labels. This step previously said GetTable shares DeleteTable's nested template. It does not: verified against the s3tables Smithy/botocore service model, GetTable is the only operation in the set with no URI labels at all. Following the old pointer would have 404'd every GetTable against real AWS, and no transport-level test would have noticed, because such a test asserts the URL the implementation itself builds, percent-encoding every interpolated segment as `microvms.ts:17` does - and verify each method and path against the S3 Tables API reference before writing, because no SDK validates them.
- [x] Add a private `call<T>(method, path, payload?)` helper in the `packages/core/src/aws/microvms.ts:124-140` shape, sending the `s3tables` service descriptor with `content-type: application/json` and parsing an empty body as `{}`.
- [x] Expose exactly nine methods in domain vocabulary - `createTableBucket`/`getTableBucket`/`deleteTableBucket`, `createNamespace`/`getNamespace`/`deleteNamespace`, `createTable`/`getTable`/`deleteTable` - each returning a narrow domain shape (ARN, name, metadata-location) rather than the raw response, and add nothing the analytics nodes do not call.
- [x] Give every `get*` an `AwsError.isNotFound` catch returning `undefined` (`packages/core/src/aws/secretsmanager.ts:65-75`), every `create*` an `isAlreadyExists` catch returning normally (`packages/core/src/aws/s3.ts:71-74`), and every `delete*` an `isNotFound` swallow so teardown is re-runnable.
- [x] Rethrow every other failure as an `AwsError` (`packages/core/src/aws/errors.ts:8`) that keeps the original `code`, `statusCode` and `requestId` and prefixes the message with the operation and the offending bucket/namespace/table name, so `isNotFound`/`isAlreadyExists` still narrow downstream and no context is lost.
- [x] Write `packages/analytics/src/aws/s3tables.test.ts` reusing the `response()` and `<client>With(transport)` helpers from `packages/core/src/aws/logs.test.ts:9-16`: one recording-transport case per operation pinning method, path and parsed body, plus an absent-resource case, an already-exists create case, and a 500 that must reject.
- [x] Export the client from `packages/analytics/src/index.ts`, keeping the barrel alphabetical. Nothing is added to `packages/core/src/index.ts`.
