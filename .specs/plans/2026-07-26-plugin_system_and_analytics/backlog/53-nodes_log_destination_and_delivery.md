## Steps

- [ ] Write `analytics-log-destination` with `dependsOn: ['analytics-firehose-stream']`, calling `putDeliveryDestination` with the stream ARN and the output format the Iceberg pipeline needs, using task 37's option rather than a second client method, under a destination name distinct from `ctx.names.deliveryDestination`.
- [ ] Record the configured output format alongside the destination ARN in the plugin's scoped state, and make `update` replace rather than mutate when the recorded format differs from the configured one — delete the destination, then re-create it — with a comment stating that the output format is immutable once a destination exists.
- [ ] Write `analytics-log-delivery` with `dependsOn: ['analytics-log-destination']`, calling `createDelivery` against the site's `ctx.names.deliverySource` with the record-field selection from `packages/analytics/src/schema.ts` and the delimiter task 37 added, and never calling `putDeliverySource`.
- [ ] Read the site's delivery-source name from `ctx.names` and the distribution ARN from `ctx.siteState`, the read-only site view on `PluginContext`, never by constructing a `StateStore` over the site's key, and fail before any call with a message naming `blogwright bootstrap` as the fix when either is absent.
- [ ] Implement the `ConflictException` retry to clear only the plugin's own delivery and destination — never the shared delivery source — with a comment stating how this deliberately differs from `packages/cli/src/nodes.ts:751-759`, whose `deleteDeliverySource` at `:758` would take the site's own CloudWatch delivery with it.
- [ ] Implement `delete` to remove the plugin's delivery before its destination and never the shared delivery source, following the ordering the comment at `packages/cli/src/nodes.ts:763-768` documents.
- [ ] Extend `packages/analytics/src/nodes.test.ts` with the recording `logsUsEast1` fake shape from `packages/cli/src/nodes.test.ts:36-77`: a format change producing delete-then-create; a create asserting `deliveriesForSource` still lists the site's CloudWatch delivery and no delete was issued against it; a `ConflictException` retry asserting `deleteDeliverySource` never appears in the call log; a teardown asserting the delivery-then-destination order and, again, no `deleteDeliverySource`.

## Definition of done

- [ ] `analytics-log-destination` creates a delivery destination pointing at the Firehose stream with the output format the Iceberg pipeline needs, and replaces rather than updates when the recorded format differs from the configured one — because the output format is immutable once a destination exists — asserted by a test that changes the format and observes a delete-then-create call sequence.
- [ ] `analytics-log-delivery` creates a delivery joining the site's delivery source to that destination with the record-field selection from `packages/analytics/src/schema.ts`, never calls `putDeliverySource`, reads the site's delivery-source name and distribution ARN through `ctx.names` and `ctx.siteState`, the read-only site view on `PluginContext` (task 01) rather than an unscoped `StateStore`, and fails before any AWS call with a message naming `blogwright bootstrap` as the fix when either is absent (negative-space test).
- [ ] The site's existing CloudWatch delivery survives: after the analytics delivery is created, a test asserts `deliveriesForSource` still lists the CloudWatch delivery and that no delete was issued against it.
- [ ] Neither the `ConflictException` retry nor `delete` ever touches the shared delivery source: the retry clears only the plugin's own delivery and destination, with a comment stating how it deliberately differs from `packages/cli/src/nodes.ts:751-759`, and `delete` removes the delivery before the destination per the ordering documented at `packages/cli/src/nodes.ts:763-768` — one test asserting the retry's call log, one asserting the teardown order, and both asserting `deleteDeliverySource` never appears.
