# Task 31 — Open the transport so a plugin can supply its own AWS services

**Implements:** [2026-07-26-cli_plugin_system.md §Plugin SPI → Plugin-supplied AWS services (Add)](../../../changes/2026-07-26-cli_plugin_system.md) (`SendOptions.service` accepts a service descriptor as well as a core key, so a plugin reaches a service core does not enumerate)
**Depends on:** —
**Produces:** `resolveEndpoint` and `SendOptions.service` accept a `{ service, signingName, global? }` descriptor as well as today's `ServiceKey`, so a plugin can sign against any AWS service without an edit to core — with every existing core client's request provably byte-identical
**Pointers:** `packages/core/src/aws/endpoint.ts:19` (the `SIGNING_NAMES` map the four keys join), `packages/core/src/aws/endpoint.ts:27-29` (the `microvms: 'lambda'` entry and its comment, which a new `lambda` key must not disturb), `packages/core/src/aws/endpoint.ts:33` (`ServiceKey`, derived from the map), `packages/core/src/aws/endpoint.ts:36` (`GLOBAL_SERVICES`, which the four keys stay out of), `packages/core/src/aws/endpoint.ts:63,75` (`canonicalHost` and its `default` branch, `` `${service}.${region}.amazonaws.com` ``), `packages/core/src/aws/endpoint.test.ts:6,16,24` (the three existing describes the new assertions join), `packages/core/src/aws/signer.ts:96,124` (`resolveEndpoint` and `SIGNING_NAMES[opts.service]` — the map's only consumers)

## Steps

- [ ] Add a `ServiceDescriptor` type to `packages/core/src/aws/endpoint.ts` — `{ service: string; signingName: string; global?: boolean }` — and widen `resolveEndpoint`'s first parameter to `ServiceKey | ServiceDescriptor`, resolving a key through `SIGNING_NAMES` exactly as today and a descriptor through its own fields. `canonicalHost`'s `default` branch (`endpoint.ts:75`) already returns `` `${service}.${region}.amazonaws.com` ``, so a descriptor for an unknown service resolves correctly with no new host logic.
- [ ] Widen `SendOptions.service` (`packages/core/src/aws/signer.ts:27`) the same way, and replace the `SIGNING_NAMES[opts.service]` lookup (`:124`) with one resolution helper that accepts either form. `GLOBAL_SERVICES` (`endpoint.ts:36`) stays the source of truth for core's own keys; a descriptor carries its own `global` flag.
- [ ] Leave `SIGNING_NAMES` closed around the services core itself uses — do NOT add `s3tables`, `firehose`, `glue` or `lambda`. They belong to the analytics plugin (tasks 33–35), which supplies them as descriptors; adding them here would put plugin-specific surface in core and `pnpm knip` would report four exported clients nothing in core or the CLI consumes.
- [ ] Extend `packages/core/src/aws/endpoint.test.ts` (`:6,16,24`) with descriptor cases: an unknown regional service resolves to `<service>.<region>.amazonaws.com` under its own signing name; a descriptor with `global: true` signs in `us-east-1`; an endpoint override still routes a descriptor to the override origin. Assert `microvms` (`endpoint.ts:27-29`, signing name `lambda`, `/2025-09-09/` paths) is untouched.
- [ ] Prove no core client's wire format moved: extend the signer test so a request built from a `ServiceKey` and the equivalent descriptor produce byte-identical canonical requests and `Authorization` headers.
- [ ] Add `s3tables: 's3tables'`, `firehose: 'firehose'`, `glue: 'glue'` and `lambda: 'lambda'` to `SIGNING_NAMES` at `packages/core/src/aws/endpoint.ts:19`, leaving every existing entry — including the `microvms: 'lambda'` line at `:29` and the two-line comment above it — byte-identical, so `ServiceKey` at `:33` widens without any existing key changing.
- [ ] Leave `canonicalHost` (`packages/core/src/aws/endpoint.ts:63`) and `GLOBAL_SERVICES` (`:36`) unedited: the `default` branch at `:75` already yields `<service>.<region>.amazonaws.com` for all four keys, and none of the four is a global service, so both omissions are deliberate and should be stated in the change description rather than in a code comment.
- [ ] Extend the `uses canonical hosts without an override` test at `packages/core/src/aws/endpoint.test.ts:6` with `s3tables`, `firehose`, `glue` and `lambda` against `us-east-1`, keeping the existing `microvms` assertion at `:11` in place as the regression anchor and adding an assertion that `SIGNING_NAMES.microvms` is still `'lambda'`.
- [ ] Add a negative-space test asserting the four new keys sign in the region passed rather than being forced to `us-east-1` (the behaviour the `GLOBAL_SERVICES` test at `:16` pins for `iam`/`cloudfront`), and extend the override test at `:24` so each of the four routes to `http://localhost:4566` with `override: true`.

## Definition of done

- [ ] `resolveEndpoint` and `SendOptions.service` accept a `{ service, signingName, global? }` descriptor as well as today's `ServiceKey`, and the absence of a match is impossible by construction — a descriptor carries everything resolution needs.
- [ ] `SIGNING_NAMES` is byte-identical to today: it gains NO keys, and `s3tables`, `firehose`, `glue` and `lambda` appear nowhere in `packages/core`. `grep -n "s3tables\|firehose\|glue" packages/core/src/` returns nothing — those services belong to the analytics plugin, which supplies them as descriptors.
- [ ] A descriptor for an unknown regional service resolves to `<service>.<region>.amazonaws.com` under its own signing name; a descriptor with `global: true` signs in `us-east-1`; an endpoint override routes a descriptor to the override origin with `override: true` — one test each.
- [ ] `microvms` is provably undisturbed: a regression test asserts it still resolves to `lambda.<region>.amazonaws.com`, signs as `lambda`, and addresses the `/2025-09-09/` paths.
- [ ] No core client's wire format moved: a signer test asserts a request built from a `ServiceKey` and from the equivalent descriptor produce byte-identical canonical requests and `Authorization` headers.
- [ ] Meets the repo definition of done (see plan.md baseline).
- [ ] Reviewable: run `pnpm test -- endpoint` and `jj diff packages/core/src/aws/endpoint.ts`; confirm the tests cover all four new keys plus `microvms`, and the diff adds only four lines inside `SIGNING_NAMES`.
