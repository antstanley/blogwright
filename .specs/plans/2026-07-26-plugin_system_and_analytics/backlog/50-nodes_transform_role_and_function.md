## Steps

- [ ] Write `analytics-transform-role` with `dependsOn: []`: create the role through `ctx.clients.iam.ensureRole` with a Lambda trust document restating the shape at `packages/cli/src/nodes.ts:106-115`, and add a comment stating the duplication is deliberate because `LAMBDA_TRUST` is CLI-private and a plugin may not import the CLI.
- [ ] Add the `analytics-salt-secret` node ahead of the role: a Secrets Manager secret named from `config.analytics.saltSecretName` (default `<siteName>/analytics-salt`) holding a random salt, created if absent and never overwritten on reconcile — regenerating it would silently break `visitor_key` comparison across the boundary. `SecretsManagerClient` already exists in core (`packages/core/src/aws/secretsmanager.ts`), so no new client is needed; `packages/pds/src/secret.ts` is the precedent for shape and error handling.
- [ ] Apply the role's inline policy in a named helper shared by `create` and `update`, granting `logs:CreateLogStream`/`logs:PutLogEvents` on the function's own log group ARN — the `packages/cli/src/nodes.ts:212` scoping — plus `secretsmanager:GetSecretValue` on the salt secret's ARN ALONE, with no `*` resource anywhere in the document.
- [ ] Declare the function's runtime, handler, timeout and memory as named module constants and reference them from the create and update payloads, never as literals at the call site.
- [ ] Write `analytics-transform-function` with `dependsOn: ['analytics-transform-role']`: read the bundled transform's bytes through `ctx.ports.fs`, zip them the way `packageAndUploadAgent` does at `packages/cli/src/agent-package.ts:48-53`, and record the deployed source hash from task 43 into the plugin's scoped state alongside the function ARN.
- [ ] Decide and record in a comment how the code reaches the function: inline zip bytes rather than an S3 code bucket, because Lambda requires the code bucket to be in the function's own region while the site's bucket is in `config.region` and the function is pinned to `us-east-1`; confirm the inline-payload limit in the `CreateFunction` API reference and guard it with a named constant that raises naming the measured size when the bundle exceeds it.
- [ ] Gate the update on the recorded hash the way `builderImageAction` does at `packages/cli/src/nodes.ts:311-321`: an unchanged hash performs no update call, a changed hash performs one, and the decision is a pure function so it is testable without the AWS calls.
- [ ] Extend `packages/analytics/src/nodes.test.ts`: inspect the policy document for the absence of a `*` resource; assert the unchanged-hash and changed-hash update behaviour; assert `read` returns `false` without throwing when the function is absent and that `create` records the ARN; assert `delete` removes the function then the role and is re-runnable when either is already gone.
