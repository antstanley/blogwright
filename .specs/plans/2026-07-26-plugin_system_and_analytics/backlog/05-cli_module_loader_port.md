## Steps

- [ ] Define `ModuleLoader` in `packages/cli/src/ports.ts` beside `Vcs` (`packages/cli/src/ports.ts:10-15`), with `fromDir` a per-call argument rather than state fixed at construction - discovery resolves the consumer's plugins from the repo root and the CLI's bundled plugins from the CLI package directory: `resolve(specifier: string, fromDir: string)` returning a discriminated resolution result (`{ found: true; path: string } | { found: false }`, never `string | null`), `packageJsonPathFor(specifier: string, fromDir: string)` returning the same result shape, and `load(path: string)` returning the imported module as `unknown` so the caller validates at the boundary; add `loader: ModuleLoader` to the `Ports` interface at `packages/cli/src/ports.ts:24-29`.
- [ ] Implement `packageJsonPathFor` by resolving the BARE specifier and walking up from the resolved file to the nearest `package.json`, and doc-comment why it exists: `require.resolve('<name>/package.json')` throws `ERR_PACKAGE_PATH_NOT_EXPORTED` for every published package here, because their `exports` maps do not list `./package.json` (verified 2026-07-26 against `blogwright-pds`). Doc-comment the limit too: `blogwright` itself cannot be reached this way either - its `exports` map has no `.` entry, so the bare specifier throws as well - which is why task 08 locates the CLI's own package from `import.meta.url` rather than through this port.
- [ ] Write `packages/cli/src/adapters/node-module-loader.ts` as the only file owning `node:module`: `createRequire` anchored on `<fromDir>/package.json` plus `require.resolve` for `resolve`, and a dynamic `import()` over the file URL for `load`, with a module comment naming it the sole `node:module` importer.
- [ ] Translate adapter failures the way `runVcsCommand` does (`packages/cli/src/adapters/process-vcs.ts:17-26`): a module-not-found resolution returns `{ found: false }` rather than throwing, and any other failure raises an `Error` naming the specifier, the directory and the underlying message, with the original attached as `cause`.
- [ ] Extend the root `.oxlintrc.json` `no-restricted-imports` path list (`.oxlintrc.json:53-69`) with `node:module` and `module`, each carrying a message that names the `ModuleLoader` port and points at DEVELOPMENT.md §Hexagonal architecture, and confirm the existing overrides (`.oxlintrc.json:71-84`) already cover the new adapter with no new path.
- [ ] Wire `loader: opts.ports?.loader ?? createNodeModuleLoader()` into `createContext` (`packages/cli/src/context.ts:111-116`), and add a `rejectAllLoader` beside `rejectAllVcs` in `packages/cli/src/test-support.ts:91-102` whose messages name `ports.loader` as the override to set, defaulting it at `:155-160`.
- [ ] Write `packages/cli/src/adapters/node-module-loader.test.ts` as an integration test over a real directory built with `makeTempDir`/`removeTempDir` (`packages/cli/src/test-support.ts:132-139`), covering a resolvable specifier and an unresolvable one, and add the `ModuleLoader` row to DEVELOPMENT.md's ports table (`DEVELOPMENT.md:72-81`).

## Definition of done

- [ ] `ModuleLoader` exposes `resolve(specifier, fromDir)`, `packageJsonPathFor(specifier, fromDir)` and `load(path)`, and the absence of a resolution is explicit in the type - no `null` is returned for a domain value.
- [ ] `packageJsonPathFor` resolves the bare specifier and walks up to the nearest `package.json`, never resolving `<name>/package.json`. A test using the REAL adapter against this workspace returns a path for `blogwright-pds`; the same test written as `require.resolve('blogwright-pds/package.json')` throws `ERR_PACKAGE_PATH_NOT_EXPORTED`, and the task records that contrast in a comment so nobody "simplifies" it back.
- [ ] `packages/cli/src/adapters/node-module-loader.ts` is the only file outside the composition root importing `node:module`; `node:module` and `module` are in the root `.oxlintrc.json` `no-restricted-imports` paths so the discipline is mechanically enforced, and `pnpm lint` passes with no new override path (the existing `packages/cli/src/adapters/**` and `context.ts` overrides suffice).
- [ ] Adapter failures are translated into repo `Error`s naming the specifier and the directory, mirroring `createProcessVcs`, and an integration test exercises the real adapter against a real directory (`makeTempDir`/`removeTempDir`) for both a resolvable and an unresolvable specifier.
- [ ] `ports.loader` is wired in `createContext` and defaulted in `createTestContext` to a fail-fast fake whose message names the override to set - the `rejectAllVcs` pattern - and DEVELOPMENT.md §Hexagonal architecture's ports table gains a `ModuleLoader` row naming the port file, the real adapter and the test substitute.
- [ ] Meets the repo definition of done (see plan.md baseline).
- [ ] Reviewable: run `pnpm --filter blogwright test -- node-module-loader`; confirm both the resolvable and unresolvable cases pass with no registry access, then temporarily add `import { createRequire } from 'node:module'` to `packages/cli/src/commands.ts`, run `pnpm lint`, and confirm it errors with the new message.
