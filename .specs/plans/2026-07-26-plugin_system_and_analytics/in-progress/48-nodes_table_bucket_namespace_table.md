## Steps

- [ ] Creating the namespace and table through the S3 Tables control-plane API is a supported Firehose source - verified 2026-07-26 against AWS's S3 Tables + Firehose walkthrough, which uses `aws s3tables create-namespace` and `aws s3tables create-table` and then points the stream at them. Record this in the module comment, because Firehose's considerations page carries a limitation that reads as if it forbids this ("only tables created through Iceberg's GlueCatalog API"); that applies to plain Iceberg-on-S3 tables registered in Glue, not to S3 Tables reached through the `s3tablescatalog` federation. Without the note the next reader will re-litigate it.
- [ ] Write `packages/analytics/src/nodes.ts` opening with a module comment stating what the graph owns, that every resource in it is created in `us-east-1` because CloudFront standard logging accepts a Firehose stream only there, and that the nodes are typed as core's `ResourceNode` over `PluginContext` so the CLI's engine reconciles them unchanged.
- [ ] Add the plugin's own `output(ctx, id)` equivalent over the scoped store's state, mirroring `packages/cli/src/nodes.ts:20-22`, and use it to record each identifier as its resource is created rather than after the chain completes - the discipline documented at `packages/cli/src/nodes.ts:717-719`.
- [ ] Write `analytics-table-bucket` with `dependsOn: []`: `read` returns whether the bucket exists and hydrates its ARN, `create` creates it through the plugin bundle's `s3tables` client and records the ARN before any tagging or secondary call, `delete` removes it and returns without error when it is already gone.
- [ ] Write `analytics-namespace` with `dependsOn: ['analytics-table-bucket']` and `analytics-table` with `dependsOn: ['analytics-namespace']`, each following the same read/create/delete shape and recording its identifier on create.
- [ ] Build the `analytics-table` create payload from `PAGE_VIEWS_COLUMNS` and the partition constant in `packages/analytics/src/schema.ts` by mapping the column table into the API's field shape, so no column name, type or partition literal appears in `nodes.ts`.
- [ ] Take the bucket, namespace and table names from the resolved `analytics` config (task 44), where each default already carries the environment, not from `ctx.names`, and leave the environment-collision assertion with the module that owns the derivation rather than restating the rule here.
- [ ] Write `packages/analytics/src/nodes.test.ts` covering, for each of the three nodes, a present resource, an absent resource (read returns `false` without throwing), a create recording its identifier into the scoped state, and a delete against an already-absent resource; assert the create payload changes when a column in `schema.ts` is altered, and assert through a recording transport that the requests sign against `us-east-1` with `config.region` set to something else.

## Definition of done

- [ ] `analytics-table-bucket`, `analytics-namespace` and `analytics-table` each implement `read`/`create`/`delete` with `dependsOn` chaining bucket → namespace → table, record their identifiers into the plugin's scoped state as each resource is created (the incremental-recording discipline at `packages/cli/src/nodes.ts:713-719`), and reach AWS only through the plugin's own `createAnalyticsClients(ctx)` bundle (task 38) - never through `ctx.clients`, which carries only core's services - reachable from a `PluginContext` at typecheck level, with a recording-transport test asserting the calls sign against `us-east-1` while `config.region` is set to another region.
- [ ] `analytics-table` builds `page_views` from `packages/analytics/src/schema.ts`'s column set partitioned by `day` with no column name, type or partition literal of its own - a test that alters one column in `schema.ts` observes the create payload change rather than passing unchanged.
- [ ] Negative space: every `read` returns `false` without throwing when the resource is absent, and every `delete` is a no-op when the resource is already gone - one transport-mocked test per node per direction.
- [ ] The bucket, namespace and table names come from the resolved `analytics` config as task 44 settled them, not from `ctx.names`, and the test asserting two environments cannot collide lives with the module that owns the derivation rather than being restated in `nodes.test.ts`.
