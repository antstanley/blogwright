## Residue

The certificate's Residue anticipated that the CloudFront field spellings would not be verified here and would be "caught at first delivery, not here". They were verified here, against AWS's CloudFront **Standard logging reference** (`standard-logs-reference.html`) and **Configure standard logging (v2)** (`standard-logging.html`), fetched 2026-08-30. All eighteen selected names exist verbatim: the sixteen `FIELD_TO_COLUMN` keys (`x-host-header`, `cs-uri-stem`, `cs-uri-query`, `cs-method`, `sc-status`, `cs(Referer)`, `cs(User-Agent)`, `c-country`, `asn`, `x-edge-location`, `x-edge-result-type`, `sc-bytes`, `time-taken`, `sc-content-type`, `cs-protocol`, `x-edge-request-id`) plus `c-ip` and `timestamp(ms)`. Four of them (`c-country`, `asn`, `timestamp(ms)`, and the real-time set generally) are v2-only additions listed under §Access log fields, which is correct for this delivery; the rest are legacy standard-log fields v2 also accepts. The three ambiguity resolutions are all correct against AWS's own field descriptions:

- **`host` ← `x-host-header`.** AWS: `x-host-header` is "the value that the viewer included in the `Host` header … If you're using alternate domain names (CNAMEs) … this field contains the alternate domain name", while `cs(Host)` is "the domain name of the CloudFront distribution". `cs(Host)` would have made `host` a per-distribution constant. Right call.
- **`result_type` ← `x-edge-result-type`.** AWS: "How the server classified the response after the last byte left the server" - the `Hit`/`RefreshHit`/`Miss`/`Error`/`Redirect` classification. `x-edge-response-result-type` differs only in the mid-response-disconnect case and `x-edge-detailed-result-type` only adds Origin Shield and error detail, neither of which this table has a column for. Right call.
- **`bytes_sent` ← `sc-bytes`.** AWS: "The total number of bytes that the server sent to the viewer in response to the request, including headers." `cs-bytes` is the viewer→server direction and `sc-content-len` is only the `Content-Length` header value. Right call.

Two quality findings, neither defeating an obligation:

1. **Two of the 34 tests are knip artifacts, not coverage.** The implementer reported that knip flagged `TIMESTAMP_MS_FIELD` and `IcebergType` as unused and that this was "fixed by adding direct test coverage rather than suppressing". A negative control disproves the second half: removing exactly those two additions - the `it('selects the millisecond-timestamp field …')` block (`schema.test.ts:113-117`) and the `KNOWN_ICEBERG_TYPES` constant with its `it('only uses documented Iceberg primitive types')` (`schema.test.ts:19-27, 70-74`) - makes `pnpm knip` report exactly `TIMESTAMP_MS_FIELD` and `IcebergType` and nothing else. Neither block can fail. All three assertions in the timestamp test are true by construction (`DERIVATION_ONLY_FIELDS` is literally `[VIEWER_IP_FIELD, TIMESTAMP_MS_FIELD]` and `CLOUDFRONT_RECORD_FIELDS` spreads it), and the Iceberg-type assertion cannot fail while `pnpm typecheck` is green, because `PAGE_VIEWS_COLUMNS` is declared `as const satisfies readonly PageViewsColumn[]` and `PageViewsColumn.icebergType` is already typed `IcebergType`. This is the third knip-shaped artifact in this build. The better options are to unexport `IcebergType` (nothing outside the module needs it - task 48 can reach it as `PageViewsColumn['icebergType']`), and for `TIMESTAMP_MS_FIELD`, which task 40 genuinely will import, either unexport it until task 40 adds the `export` alongside its first consumer, or add a narrowly scoped `ignoreExports` entry to `knip.json`'s `packages/analytics` workspace with a comment naming task 40.
2. **`CLOUDFRONT_RECORD_FIELDS` loses its literal types.** Because it spreads `Object.keys(FIELD_TO_COLUMN)` (typed `string[]`), the `as const` yields `readonly [...string[], "c-ip", "timestamp(ms)"]` - the sixteen mapped field names are `string`, not literals. Harmless for task 53, whose `recordFields` parameter takes strings, but the `as const` buys less than it appears to. A `keyof typeof FIELD_TO_COLUMN` assertion on the spread would restore it.

The `day` partition transform (identity on a date column versus a `day()` transform over `event_time`) remains, as authored, task 48's to settle.
